# FS-04 resource qualification

The inherited FS-00 read, static-config, evidence, snapshot and generation ceilings are unchanged. Added extraction uses the existing cooperative generation boundary, 100,000 visited syntax nodes per file, 20,000 facts per file, 10,000 route registrations, 64 proof/config dependencies, depth 32 for literal config/exports and depth 64 for export/action/client ownership expansion. Overflow or cancellation cannot publish a partial generation over the previous complete SQLite snapshot.

Windows measurements are retained in `evidence/resource-measurements.json`: five cold processes and twenty retained-session analyses following one warmup for each of five tuples. Timing medians/p95, snapshot bytes, fact counts, deadline hits, RSS and Windows committed-memory counters are reported separately. Counter sampling at 50 ms can miss transient peaks. These small synthetic fixtures do not qualify whole-engine worst-case memory; the 512 MiB new-language worker budget belongs to subsequent phases.

Historical comparisons use identical retained F02 source bytes, runtime, CPU, TS and ts-morph versions: five fresh sessions and twenty retained-session runs, repeated three times. Compare with both accepted FS-02 and FS-03 medians. A repeated increase above 20% requires investigation, not a silently widened budget. Final outcomes are in `evidence/resource-summary.json` and `evidence/historical-performance.json`.

Controlled fixtures remain authoritative. `F04-node-next/fixture.json` supplies Next App/Pages, server-action, layout, dynamic route, context, slot and Node entry source; tuple derivatives change only exact package versions. `node.json` supplies native imports/self exports/CJS/listeners/events/workers. Tests add mutation, configuration, dispatch, alias, encoding, version and cancellation negatives. FS-01/02 and the complete FS-03 limit/read-policy/security suites remain regression gates. No external application is a test oracle.
