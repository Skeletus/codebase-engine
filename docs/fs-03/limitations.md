# Qualified scope and unsupported boundaries

FS-03 mandatory acceptance gates are complete. These are boundaries of the qualified static patterns, not guessed relationships or universal runtime support. Aggregate runtime capabilities stay partial; per-pattern qualification records define supported scope.

- Exact declared Vite/React/DOM/Router tuples only. Ranges/workspace versions and Vite 7 SSR remain unqualified/blocked. Analysis never installs or loads inspected dependencies to infer their effective runtime version.
- Official React plugin default/automatic JSX and literal react import source are qualified. SWC, Compiler/Babel extensions, classic/custom JSX, dynamic plugin lists, mutation/shadowing, define/experimental/OXC/esbuild transforms and custom worker/bundler hooks remain boundaries. Configuration is text, never invoked.
- Conditional exports cover protected current-package self-reference with exact literal subpaths/targets and ordered supported conditions. Wildcards, arrays/null, mixed keys, ambiguous names and external installed dependencies remain unresolved. Sibling metadata alone does not prove a workspace dependency link.
- Public assets use literal URL imports and protected default/custom publicDir; false disables mapping. Remote/computed URLs, custom transforms and inaccessible assets remain unresolved. CSS/raw/url/worker/glob facts identify source dependencies/inputs, not generated implementations or evaluated export values.
- TS paths cover Vite 8 opt-in, nearest literal JSON and one target outside dependency directories. Explicit alternate tsconfig selection, roots below node_modules, extends/references, multiple targets, baseUrl fallback and plugin paths remain boundaries. General cwd-dependent relative-alias forms are not qualified beyond controlled named targets.
- Components/hooks/context/wrappers require unique stable lexical declarations and supported syntax/API/version. Null-return/createElement-only classification, custom HOCs, arbitrary receiving callback props/spreads, computed lazy mappings, dynamic context/promise inputs, static/decorated/dynamically replaced class lifecycle methods and unproved dispatch remain unresolved. No scheduling, rendering or handler execution is inferred.
- Navigation requires a supported literal matcher and one proved router scope. Options/basename, relative/query/hash destinations, data-router provider ownership, deeper unproved component ownership, optional/encoded declaration patterns and custom factories remain boundaries. Unknown/dynamic/truncated sets prevent unique navigation claims; precedence stays null.
- Development proxies establish development-only routing facts. Unknown rewrite/request hooks stay gaps. No production deployment/origin identity or cross-stack links are inferred; linking belongs to FS-10.
- Measurements establish feasibility for the recorded corpus. RSS and commit differ; 50ms sampling can miss peaks. Historical comparison uses the identical small TS/JS corpus. Future Python/Flow/native worker startup/IPC/OOM/512 MiB gates and a whole-engine worst-case memory guarantee are outside FS-03.

Pinned public repositories are supplementary, read-only validation: exact commits/source inventories are retained while their range/workspace/plugin patterns remain unqualified. They never replace fixtures. See [fixture design](fixture-design.md), [matrix](support-matrix.md) and [qualification](qualification.json).
