# FS-00 fixture design

Synthetic, licensed first-party fixtures are the default. No customer repository, secrets, dependency source corpus or new Laya training set. Fixture installation/build/oracles are developer-only, explicitly invoked and network-disconnected after provisioning. Customer analysis receives the resulting fixture source/metadata and never invokes its programs. Source dependency fixtures must be in the selected root; SDK/dependency internals remain external.

Each fixture has an ID, owner phase, tuple/profile/variant, source byte SHA-256, permitted inventory, expected verified facts with ranges/witnesses, candidates, gap reason/location, forbidden facts, counts and resource outcome. Golden facts use deterministic semantic keys rather than wall-clock/order fields. Native registration oracles are declarations/annotations from the controlled compiler fixture, not runtime invocation claims.

For every supported binding rule there must be at least one positive and one negative with a precise missing-proof reason. Pair platforms and development/production rather than merging their expected facts. Keep the observed valid compact Kotlin failure as a non-qualification fixture; record the parser limitation without claiming the source is invalid Kotlin. Every dynamic expression must assert the forbidden guessed relationship, not merely the presence of some diagnostic.

Planned structure when its phase is approved: tests/fixtures/framework-support/<ID>/<tuple>/source, fixture.json, expected.json, oracle.json and license.txt; tests/framework-support/fs-NN.test.ts. This is a design, not a fixture corpus created by FS-00. A runner must accept explicit tuple/profile filters, return nonzero on mismatch/missing oracle and print counts for expected facts, candidates, gaps and forbidden facts. Never update golden files automatically in acceptance mode. Store oracle tool versions, command, fixture hash and output hash; fail a qualified badge if the oracle is absent or from another tuple.

Qualification layers: syntax sample -> resolver/semantic golden -> independent framework oracle -> lifecycle/persistence -> packaged Windows offline. FS-00 only ran the first layer plus existing product baseline and isolated containment/contract feasibility. All later layers remain required by their specifications.
