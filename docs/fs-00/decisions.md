# FS-00 architecture decisions

Accepted design baseline, 2026-10-06. Owner of every decision: the implementing engineer for the listed phase; the FS-00 author is responsible for this selection and evidence. These decisions bind the later specifications. Implementation and new production packages still need their separately authorized phase. Product principles remain in [CLAUDE.md](../../CLAUDE.md); this record supplies the framework-specific rationale.

## ADR-00-01 — Qualification is a bounded tuple (FS-01–10)

Select the exact tuples in [the manifest](support-manifest.json), rather than compatible-looking Cartesian products. Installed Next 16.3.6, React 19.2.8, TS 5.9.3 and Node 24.19.0 are preservation anchors. New targets are **planned**, never qualified by metadata checks or parser acceptance alone. Each capability requires version, syntax pattern, resolver profile, variant, extractor version, fixture outcomes and packaged Windows ledger. An unrecognized version is unsupported for the qualified badge; useful extraction can remain partial. Patch upgrades require the tuple's suite again. This bounds a reproducible claim while retaining useful facts.

Gate: FS-01 capability validation; per-stack oracles; FS-09/10 installed qualification. Primary npm/PyPI versions, constraints and integrity are retained in [registry evidence](evidence/registry.json), [supplement](evidence/registry-supplement.json), and [Expo/Node compatibility evidence](evidence/compatibility.json). These are availability/compatibility evidence, not runtime tests.

## ADR-00-02 — Packaged syntax parsing for Python (FS-05)

Select `web-tree-sitter@0.25.10` with `tree-sitter-python@0.25.0` WASM. Ship approved, hashed resources inside the existing Node engine distribution; use no customer Python installation, Pyright daemon, native npm build, or executed imports. Adapter-owned lexical scopes/import resolution supply conservative semantics. CPython 3.13.3 is an existing development oracle only; future fixtures use CPython 3.12.15/3.13.16. Neither is shipped. Parser grammar version and Python language fixture version are separate.

The experiment accepted Django URL syntax, async/match and generic type aliases, recovered malformed input, parsed an execution sentinel without executing it, compared incremental/full results, and cancelled/reset successfully. CPython AST columns are UTF-8 byte offsets; the selected web binding reports UTF-16 string offsets. A bundled CPython AST worker would add another runtime, platform packaging and import-execution exposure without solving semantic resolution. It remains an oracle, not a fallback silently run on customer code. Native Tree-sitter bindings and Pyright are deferred.

Gate: FS-05 import/scoping/encoding fixtures and Windows without Python/PATH; ABI and asset checks; worker time/memory failures become gaps. [Python AST documentation](https://docs.python.org/3/library/ast.html), [Windows embeddable package](https://docs.python.org/3/using/windows.html#the-embeddable-package), [web binding](https://github.com/tree-sitter/tree-sitter/blob/v0.25.10/lib/binding_web/README.md). See [experiments](experiments.md).

## ADR-00-03 — Flow syntax through Hermes (FS-07)

Select `hermes-parser@0.25.1`, ESTree with Flow enabled, behind the language-session interface. Pin this **grammar release**, not an untested promise for all Flow typechecker versions. Qualify classic Flow types, enums, component declarations and hook declarations individually. Existing Babel 7.29.9 handled classic/enum syntax but rejected the modern component/hook examples; Hermes accepted all four and rejected malformed input. It supplies syntax, not Flow inference. No Babel config, transforms, plugins or repository code runs. TS/JS stays on ts-morph; do not reparse all JS with Hermes.

Gate: FS-07 scoped references, Unicode ranges, cancellation through process supervision, syntax-negative fixtures and packaged resource closure. [Hermes parser source](https://github.com/facebook/hermes/tree/main/tools/hermes-parser), local prototype and supplemental registry integrity. The approval for isolated installation does not approve a production dependency.

## ADR-00-04 — Bounded native adapters, no compiler services (FS-08)

Use the same WASM worker with Java 0.23.5, scoped Kotlin grammar 1.1.0, Swift 0.7.1 official release WASM, Objective-C 3.0.2. Grammar licenses are MIT. Java 17, Kotlin 2.0.21, Swift 5.9.2 and Clang 18.1.8 Objective-C are fixture dialect/oracle targets, not full compiler support. No JDK, Gradle, Kotlin compiler, SourceKit, Xcode, clang or CocoaPods is required by customer analysis. C++, JSI, macros, reflection, compiler-generated dispatch and third-party native implementations stop at a boundary.

Supported native facts are first-party declarations and uniquely proven local references/direct calls: nonoverloaded unqualified helper calls in the same class; explicit `self`/`this` private or final helper calls; Objective-C exact `self` selectors only where the source-local target is unique and supported dispatch proof holds. Overridable/dynamic receiver dispatch stays a candidate or gap. Registration mapping requires literal exported name, matching spec method/selector, compatible platform and explicit source registration evidence; name similarity never proves a bridge. Swift-to-ObjC needs explicit `@objc` name/selector and supported registration; missing generated code is a gap. Imported SDK types can be external boundaries without indexing SDK sources.

Python/Java/Swift/ObjC and a multiline Kotlin bridge passed syntax/reuse/cancellation tests. The Kotlin grammar rejected a valid compact semicolon example. That example must remain a known negative: `unsupported-syntax`; do not infer calls from its recovery tree. The alternate Kotlin 0.3.8 npm package lacks WASM and is rejected for offline portable packaging. Swift npm 0.7.1 lacks WASM too, but its official release provides a tested artifact; pin its SHA-256, never download it at customer startup.

Gate: FS-08 native golden AST/schema tests, positive/negative bridge pairs, compiler fixture oracles on suitable developer hosts, Windows offline parsing and incomplete-code boundaries. An iOS-source analysis claim does not certify iOS runtime execution. [Swift release](https://github.com/alex-pinkus/tree-sitter-swift/releases/tag/0.7.1), [Kotlin grammar](https://github.com/tree-sitter-grammars/tree-sitter-kotlin), [Objective-C grammar](https://github.com/tree-sitter-grammars/tree-sitter-objc).

## ADR-00-05 — Isolate parsers and contain Windows memory (FS-05/07/08/09)

One parser child process per active engine generation, maximum one concurrently. Generalize existing host supervision, extending its Windows Job Object to committed-memory limits and kill-on-close. The parent alone reads authorized source; the worker receives bytes and approved asset identifiers. This interface is not an OS network/filesystem sandbox: enforce no repository execution and no parser filesystem authority in code and tests, and do not advertise it as one.

Select 512 MiB process committed memory, 128 MiB JS old-space and worker-only flags `--wasm-num-compilation-tasks=1 --no-wasm-tier-up --no-wasm-dynamic-tiering`. Keep the main engine and Laya unchanged. Default flags exhausted the 512 MiB job on Swift stress; controlled flags passed 100 and 1,000 declarations at approximately 72 MiB peak committed memory. Forced 512 MiB allocation failed, a fresh child recovered, and a 10 ms startup deadline killed the job. Cooperative parse cancellation/reset also passed. Exit zero after kill is not success: timeout state takes precedence.

Gate: FS-09 packaged Node validates these version-sensitive flags before readiness; startup failure produces `parser-unavailable`, keeps TS/JS usable; allocation/deadline failure produces `resource-limit` and no partial facts. Revalidate on Node/parser upgrade. Existing supervisor must assign the job before accepting worker work. Native process IPC is versioned and bounded; AST trees never cross it. [Windows memory limits](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information), [job flags](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_limit_information).

## ADR-00-06 — Extend evidence; preserve imports and exact Impact (FS-01)

Keep file import relationships as the existing compatibility projection. Add declaration, call, framework binding, endpoint registration, request and link records beside it. Every new verified fact has hash-bound half-open ranges, extractor/version and all source/config witnesses used in the proof. Candidates are a separate collection with bounded alternatives and missing reasons. Gaps are first-class and retain permitted occurrence witnesses. Neither candidates nor framework bindings alter existing import degrees, structural Impact, Laya features or file paths.

Endpoint registration IDs are deterministic from normalized relative path, registration source range, registration kind and variant ID, not array indices or method/path text alone. Route identity and registration identity differ: two registrations of one handler remain two facts. Methods are `{state: known|unknown|all, values: [...]}`; known values are uppercase tokens, unknown has no guessed GET. Matchers are structured segments (literal, named parameter with supported converter, catch-all), explicit slash/case/encoding rules, and `unsupported` for uninterpreted regex. Preserve raw display pattern. A pattern is not automatically a concrete request URL. Framework-implied HEAD/OPTIONS must have explicit framework-rule evidence for the selected version; do not synthesize them for arbitrary handlers.

Gate: FS-01 validators reject missing proof/unknown enums/duplicate IDs/broken endpoints/candidate promotion. FS-04/06 qualify method/matcher semantics. Existing first-occurrence import evidence remains equivalent.

## ADR-00-07 — Original-source UTF-16 coordinates (FS-01/05/07/08)

Canonical ranges use zero-based UTF-16 code units, half-open `[start,end)`, against the exact decoded original text; displayed line/column are one-based. Hash original bytes as today. Preserve CRLF, BOM and combining characters: no newline or Unicode normalization. TS/Hermes/web-tree-sitter adapters declare their units; tested web-tree-sitter string API already uses UTF-16. A future byte-based API needs a validated UTF-8 byte-boundary map, with surrogate/interior-byte positions rejected. Never apply CPython byte offsets directly to UTF-16.

Initial added-language encoding support: valid UTF-8/ASCII, optional UTF-8 BOM. Python coding cookie agreeing with these is accepted; non-UTF-8 cookies, invalid bytes and UTF-16 encodings are explicit encoding gaps, not replacement-character facts. Existing TS/JS decoding is preserved; broaden it only through a separately specified compatibility change. Gate: Unicode/CRLF/BOM/combining fixtures, invalid byte boundaries, current-hash/stale-range evidence. [Contract results](evidence/contract-results.json) demonstrate the byte/unit difference and existing TS offsets.

## ADR-00-08 — Snapshot v3, retain v2 and reanalyze (FS-01/09)

Next shared canonical contract is v3; parser legacy schema4 is independent. Do not reinterpret v2 as v3 or invent empty capability/variant proofs. Retain the old complete payload; expose incompatible/reanalysis-required state; analyze locally into a new complete v3 generation and atomically switch publication only on success. Failure/cancellation retains the old payload and its explicit compatibility status. New client does not send v3 to an old validator/worker; handshake advertises versions. No eager database schema migration is selected because serialized snapshot payload columns can retain both versions; if new settings need columns, specify a transactional additive migration in FS-09. Reinstall/downgrade must not destroy unsupported payloads.

Gate: v2 payload byte/content round trip, unsupported version rejection, cancelled/failed reanalysis, rollback/downgrade, WAL/transaction integrity. Existing validator already rejects v3 and null route methods; [experiment](evidence/contract-results.json) proves migration is required, not implemented.

## ADR-00-09 — Explicit variants and protected resolution (FS-02)

Profile key: project ID + language/resolver ID + pinned semantics version + environment/platform + conditions + config witness hashes. Facts carry variant IDs; no implicit union across browser/server, development/production, Android/iOS or Python environments. Default web view is browser-development; Node view is server-development; RN view Android-development, with an explicit iOS selector; Python is one static declared environment per project, never inferred from global machine packages. Missing selection yields `variant-not-selected` for requests needing it. Keep prior TS/JS behavior through a legacy wrapper until a qualified new profile is explicitly available.

Static config is a bounded literal evaluator: arrays/objects/literals, supported local immutable constants, selected property access and whitelisted config wrappers. No function calls, env execution, plugins or getters. A branch depending on unknown input yields conditional facts/gaps; no guessed defaults. Supported globs are bounded and operate only on authorized inventory. Resolution results are internal/external/excluded/unresolved with reason and witnesses. Node runtime imports and TS type resolution are distinct; Vite browser conditions, Metro platform extensions and Python package roots are distinct profiles.

Read metadata through RepositoryReader. Permit narrowly named first-party package/lock/tsconfig/Vite/Next/Metro/Python/Django metadata with size checks; lockfiles may identify package versions without dependency-source indexing. No permission to traverse node_modules, SDKs, venvs, generated sources, dotdirs, symlink escapes or `.env` secrets. A reviewed generated-source exception needs its own fixture/authorization; unavailable native codegen stays a gap. Gate: FS-02 escape/getter/execution-sentinel/config-cycle tests and independent profile oracles.

## ADR-00-10 — Origin evidence precedes cross-stack linking (FS-10)

Definitive static binding requires known method, compatible selected variants, supported path/matcher semantics, uniquely established service/origin and ordered rewrite/base-path proof. Co-location, package name, CORS settings, Django ALLOWED_HOSTS, a dev server's default port and matching route text do not establish deployment identity. Browser relative requests inherit a document origin only when that origin is evidenced; RN/server relative URLs never borrow browser semantics. Do not read `.env` or contact services to discover deployment.

Accept literal public configuration or explicit source/config routing chain with all witnesses. Separate development from production mappings. A user-entered local service map is `assumed-binding` with assumption ID/version, displayed as such; it never becomes a verified source-derived fact or enters exact Impact. Multiple surviving registrations produce bounded candidates; unknown origin/method or unsupported matcher produces a gap. If candidates overflow, report truncation and prohibit unique promotion. Model rewrite precedence explicitly; ambiguous/dynamic branches stop linkage. No runtime success claim.

Gate: FS-10 origin truth table, duplicate services, method mismatch, percent-encoding/slash semantics, unknown env and conflicting rewrite fixtures; installed offline qualification. The [contract experiment](evidence/contract-results.json) validates the policy truth table only, not a production matcher.

## ADR-00-11 — Frozen Laya and optional explanations (FS-09)

Keep the current artifact, file candidate IDs, input/features, score validation and ranking limits. New domains use deterministic baseline traversal until a domain qualification ledger explicitly permits existing frozen ranking. No new training/customer corpus or implicit native-symbol ranking. Explanation extensions use the same exact preview/consent/digest/cache boundary; parser workers make no provider requests. Gate: artifact hash, unchanged feature vectors/structural degrees, invalid-candidate fallback, stale consent and provider-offline usefulness.

## ADR-00-12 — Measured budgets and synthetic fixtures (all phases)

Retain inherited read/protocol/snapshot limits. Adopt [resource budgets](resource-budgets.md) and [fixture design](fixture-design.md). Measurements establish feasibility on this host; they do not prove future worst-case throughput. Every added limit has below/at/above and recovery fixtures, and reports a typed gap/coverage count. Oracles may execute **synthetic fixtures only** on developer hosts, with pinned dependencies and explicit opt-in; customer analysis never runs them. Every capability needs a positive and an adversarial case. Gate: per-phase suites and integrated Windows ledger; budgets cannot be raised silently to hide a fixture failure.
