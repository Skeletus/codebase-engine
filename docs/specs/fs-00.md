# FS-00 — Decisions and qualification baseline

Status: authorized by user, completed planning/experiment gate. Scope is decisions, baseline verification, isolated experiments and specifications only. The [original roadmap](../framework-support-implementation-plan.md) retains the phase dependencies and product constraints.

Deliverables: [decision records](../fs-00/decisions.md), [exact support manifest](../fs-00/support-manifest.json), [qualification matrix](../fs-00/qualification-matrix.md), [regression inventory](../fs-00/regression-baseline.md), [resource budgets](../fs-00/resource-budgets.md), [fixture design](../fs-00/fixture-design.md), [experiment record](../fs-00/experiments.md), and executable specifications [FS-01](fs-01.md) through [FS-10](fs-10.md).

## Acceptance procedure

1. Every Section 7 blocking decision has a selected direction, rationale, accountable phase owner, evidence and later validation gate in ADR-00-01 through ADR-00-12. New version targets must be exact and clearly unqualified until their own suite passes.
2. Python/native parser feasibility, Flow grammar selection, source positions, snapshot compatibility and Windows resource containment have retained synthetic experiment outcomes. Known parser limits and failed trials are published, not erased or guessed away.
3. Existing verification commands pass or an explicit baseline limitation is recorded. Hash-check every pre-existing tracked/nonignored untracked file against the before ledger; no production behavior, dependency/configuration, accepted UI, model or unrelated work changes.
4. Each later phase specification has dependency, scope, extension anchors, ordered tasks, fixture IDs, executable verification procedure, acceptance and deliverables. No subsequent implementation starts from this gate alone.
5. Manifest and evidence JSON validate; local deliverable links resolve; experiment installations are removed after recording asset/license/package integrity. No commit, push, retraining or new installer publication.

Recheck with `Get-Content docs/fs-00/experiments/verify-deliverables.txt -Raw | node`. Existing baseline is reproducible through `powershell -File docs/fs-00/experiments/baseline.ps1 -Run` (regenerates ignored build outputs and evidence, without installing dependencies). Parser experiments require separately approved isolated provisioning as recorded in the experiment document.

Completion evidence and limitations are in [FS-00 report](../fs-00/README.md). This acceptance means the design baseline is resolved; it does not qualify unimplemented frameworks, installed GUI workflows or future parser/compiler oracles.
