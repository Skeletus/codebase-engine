# FS-07 implementation decisions

## Shared evidence and composition

Extend the accepted foundations. Snapshot v3 and existing binding/registration kinds remain unchanged. Framework registration, composition, lifecycle, events and navigation do not become lexical CALLS edges. Platform facts carry their selected variant; an unlabelled Flow import/call requires agreement across every selected Metro profile.

TS/JS reuses the accepted React extractor. Flow remains a supervised language adapter emitting validated neutral facts. Its private AST does not enter graph, storage or UI algorithms. Flow framework/native intent extraction is unfinished; capability assessments remain partial with no complete badge.

## Protected Metro authority

The resolver consumes protected inventory and explicit package links. No inspected configuration, application, plugin, transform or package initializer executes. Exact exports targets do not receive platform/extension expansion. Qualified lenient fallback, supported target arrays, package imports and literal redirects were added from independently pinned oracles. Unsupported shapes, custom resolvers and unestablished links remain boundaries.

Literal getDefaultConfig(__dirname) and bare-RN mergeConfig composition are interpreted as bounded data over pinned defaults. Helpers are never imported or invoked. Expo is qualified separately and does not borrow bare-RN helper exports. Unknown helpers, mutation, callbacks and unsupported fields remain gaps.

Directory exclusions apply to directory segments, not the stem of an ordinary filename such as Target.js. Canonical ownership, protected inventory and read policy remain authoritative.

## Platform, navigation and linking

Literal imported Platform.OS conditions and Platform.select alternatives select framework/dependency facts for Android or iOS. Unknown expressions, spreads and cross-file SDK mutation withhold targets and retain gaps. Named and namespace SDK identities share the mutation guard. Lexical behavior and exact Impact are preserved.

Navigation requires exact package identities and established navigator/screen context. Literal nested actions follow proven ancestry. Conditional/callback registrations cannot prove a uniquely available target. Ambiguous navigator ownership remains unresolved.

Expo routes use owned inventory and supported static root/configuration evidence. Platform siblings require a universal fallback established independently by each Router oracle. Array groups expand into logical contexts with distinct group-qualified raw patterns/IDs; URL matchers retain the group-free path. Shared URLs remain ambiguous; exact group-qualified hrefs require the full declared group sequence. Layout, group and dynamic-segment witnesses are separate from calls. Dynamic roots/plugins/configuration withhold route claims. Broader route/settings/href matrices remain unfinished.

Literal package main expo-router/entry binds a witnessed callable root layout; missing generated layouts remain boundaries. The shipped desktop/CLI request both mobile profiles, so the existing entry chooser can select either variant without UI/protocol changes or filesystem mutation. Direct adapter APIs retain explicit mode options and their accepted default.

Declared URL prefixes establish configuration facts. Linking.openURL does not prove the installed native receiver; it retains unknown-origin candidates. No later cross-stack deployment/origin work is introduced.

## Native boundary inventory

TurboModule interfaces/registry references, NativeModules, codegen component/commands metadata, legacy component declarations, UIManager and NativeEventEmitter retain source-backed boundary operations and gaps. Generated/native implementations are not followed. Spelling-only JSI/proxy calls are gaps, not verified API identities. Java, Kotlin, Swift, Objective-C and C++ implementations remain outside analysis.

## Resources and verification

Accepted source, syntax, fact, route and snapshot budgets are unchanged. Route overflow discards the candidate publication and retains the previous complete snapshot. Unavailable/corrupt Flow assets never trigger TS grammar fallback.

Historical performance restores the captured accepted FS-06 worktree sources and validates their hashes. Five cold and twenty warm runs compare the same controlled unchanged TS/JS corpus. Parent RSS and Windows job peak commitment remain separate measurements.

A concurrent run hit the unchanged parser startup deadline. Failure logs remain retained; final sequential reruns must pass without weakening deadlines or skipping cases. No FS-08 work, inspected execution, Laya change/retraining, UI redesign, commit or push is included.
